# 후보 0개 복구 및 핵심 키워드 추천 설계

## 목표

- 모든 후보가 제외된 세션에서 방장이 `새 메뉴 추천받기`를 눌러 같은 세션을 계속 진행한다.
- `멕시코식`처럼 특정 음식권을 오늘의 핵심 선호로 입력하면 관련 메뉴를 최대 10개 추천한다.

## 후보 0개 상태 흐름

메뉴 투표 마감 결과 남은 후보가 0개여도 세션을 `MENU_SELECTION`으로 전환한다. 프론트는 이미 이 상태에서 방장에게 재추천 버튼을 노출하므로 기존 `PUT .../menu-candidates/re-recommend` API를 그대로 사용한다.

재추천 API는 다음 두 상태를 처리한다.

- `MENU_SELECTION`이며 남은 후보가 0개 또는 1개: `MENU_RECOMMENDING`으로 전환하고 `SurveyRequested`를 발행한다.
- 이전 코드로 인해 이미 `MENU_RECOMMENDING`에 갇혔으며 남은 후보가 0개: 상태를 다시 변경하지 않고 `SurveyRequested`를 발행해 현재 세션을 복구한다.

남은 후보가 2개 이상이거나 다른 상태인 요청은 기존처럼 거부한다.

## 핵심 키워드 추천

현재 추천은 회원 취향과 인기도로 상위 30개를 만든 뒤 OpenAI가 그 안에서만 선택한다. 당일 키워드는 OpenAI 단계에만 전달되므로 관련 메뉴가 상위 30개 밖이면 선택할 수 없다.

결정론 필터가 알레르기, 회원 제외 메뉴, 이전 라운드 메뉴를 먼저 제거한 뒤 최대 250개를 OpenAI 후보로 전달한다. 현재 메뉴 마스터 208개 전체를 수용하면서 안전 필터와 중복 제외는 유지한다.

OpenAI 규칙은 `오늘의 핵심 선호`가 음식권, 맛, 온도, 재료, 식감, 음식 형태, 식사 상황을 명시하면 의미상 맞는 후보를 우선하고, 명확한 조건과 무관한 메뉴를 개수를 채우기 위해 섞지 않도록 강화한다. 해당 조건의 안전한 후보가 10개보다 적으면 있는 만큼만 반환한다.

## 멕시코 메뉴 데이터

기존 `퀘사디아`, `부리토`에 다음 8개를 추가한다.

- 타코
- 엔칠라다
- 나초
- 파히타
- 칠리 콘 카르네
- 케사비리아
- 타말
- 포솔레

현재 DB에도 바로 적용할 수 있도록 멱등 SQL 파일을 제공한다. 메뉴는 기존 `양식` 카테고리를 사용하고 대표 조리법 기준 알레르기 관계를 함께 추가한다.

## 오류 처리

- AI가 조건에 맞는 메뉴를 고르지 못한 경우 기존 결정론 대체 흐름은 유지한다.
- 재추천 복구 요청은 후보 0개인 기존 `MENU_RECOMMENDING` 세션에만 허용해 일반 중복 요청 범위를 넓히지 않는다.
- DB 스크립트는 `ON DUPLICATE KEY UPDATE`와 `INSERT IGNORE`를 사용해 재실행할 수 있게 한다.

## 테스트

- 후보 0개 마감이 `MENU_SELECTION`으로 전환되는 서비스 테스트
- 기존 `MENU_RECOMMENDING` + 후보 0개 세션이 추천 이벤트로 복구되는 서비스 테스트
- 후보 2개 이상 재추천 거부 회귀 테스트 유지
- 추천 서비스가 전체 후보 풀 크기를 요청하고 당일 키워드를 전달하는 테스트
- OpenAI 프롬프트가 특정 음식권 핵심 선호에 무관한 메뉴를 섞지 않도록 지시하는 테스트
- 코어·클라이언트 전체 테스트와 API 조립 실행
