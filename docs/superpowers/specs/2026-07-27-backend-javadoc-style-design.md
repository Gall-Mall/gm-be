# 백엔드 추가 코드 Javadoc 및 스타일 보강 설계

## 범위

현재 `demo/backend-completion-20260726` 브랜치에서 기준 커밋 이후 작업 트리에 추가된 백엔드 운영 Java 코드만 대상으로 한다. 테스트 코드, SQL, 설정 파일, 프론트 코드는 제외한다.

## 주석 기준

- 새로 추가한 클래스·레코드·인터페이스에는 클래스 수준 Javadoc을 작성한다.
- 새로 추가한 모든 메서드는 접근 제한자와 관계없이 Javadoc을 작성한다.
- 공개 메서드는 역할을 설명하고 필요한 경우 `@param`, `@return`, `@throws`를 기존 프로젝트 문체에 맞춰 작성한다.
- private 헬퍼는 구현을 반복하지 않고 책임과 호출 목적을 한 문장으로 설명한다.
- 트랜잭션 경계, 상태 전환, 커밋 이후 이벤트, 복구·멱등 처리처럼 코드만으로 의도가 분명하지 않은 부분은 인라인 주석을 유지하거나 보강한다.
- 대입, 단순 반환, 자명한 매핑을 그대로 읽어주는 인라인 주석은 추가하지 않는다.

## 스타일 기준

- 기존 코드의 `/** ... */` Javadoc 형식과 한국어 서술형 문체를 유지한다.
- 클래스 설명은 도메인 책임을 한 문장으로 요약한다.
- 메서드 설명은 “무엇을 하는지”를 먼저 쓰고 구현 상세는 필요한 경우에만 보충한다.
- 이미 충분한 Javadoc이 있는 메서드는 중복 주석을 추가하지 않는다.
- 주석 보강 과정에서 메서드명, 시그니처, 로직, 예외, API 경로를 변경하지 않는다.

## 검증

- 작업 전후 production Java diff에서 추가 메서드 시그니처를 다시 추출해 Javadoc 누락을 점검한다.
- `git diff --check`로 공백 오류를 확인한다.
- 코어·클라이언트 테스트와 API 조립으로 주석 변경 외 동작이 바뀌지 않았음을 확인한다.
